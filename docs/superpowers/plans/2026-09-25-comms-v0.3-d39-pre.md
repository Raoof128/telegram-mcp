**Status:** approved by the owner 2026-09-25 with four amendments, all folded in below: the bootstrap states (E1/E2), the E1 and E3 file rules, the R-E6 wording, and two worker failure classes (E5). Rulings R-A20 and R-E1 to R-E6 are approved. This closes missing production composition; it is not a fifth product layer.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. (The owner's standing rule for this repo: no subagents; the main session executes, test-first, inline.) Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One long-lived daemon holds `comms.db` and serves the already-built v0.3 surface for real: the local and remote MCP listeners, the webhook listener, the admin socket with every operator command working, and the background workers. D39 acceptance can then run against a running daemon instead of an in-process assembly.

**Architecture:** This tranche adds no new semantics, only composition and missing plumbing. `comms keys provision` creates the state; `open_comms_state` opens it fail-closed. One composition root, `assemble_runtime`, is called by both the daemon and the smoke. The daemon runs that root beside its retained legacy parts: the Telethon session in `meta.db`, the legacy chain for `verify --all`, and the login handlers. Every operator command in `OPERATOR_COMMANDS` gets a handler, or it is not registered.

**Tech Stack:** Python 3.12, SQLCipher (`sqlcipher3`), `mcp` 2.2.0, uvicorn 0.53.0, starlette 1.6.0, httpx 0.28.1, Telethon 1.45.0, pytest.

## Global Constraints

- **Branch.** Work on `comms-v0.3-d39pre`, off `main` (`272dd8b`). Merge, push and tag push only with the owner's approval; local tags are fine.
- **Commits.** Commit only when the full gate log shows `GATE ok=1`. Stage named files only, and never write in-tree files while a gate runs.
- **Secrets.** Never commit, log or print Telegram credentials, session files, keys or private material. No secret in argv, env, MCP, logs or the repository (spec A13 and credential boundary line 206). Values are entered from a TTY and cross only the peer-credential admin socket.
- **Fail closed.** A check that cannot run reports that it was skipped; it never reports success. A daemon that cannot open, migrate or verify `comms.db` never starts a listener.
- **No test-only flags in production paths.** Headless daemon tests go through a `selftest-` subcommand or an injected seam, never a branch inside `run_daemon`.

- **Frozen wires stay unchanged:** TG-JCS-v1, receipt proofs v1/v2, call binding, the `comms-*` domains in `core/domains.py`, `tgml1`, the key-id format, the catalog pin (`4380d085…`) and `EXPECTED_TOOLS`.
- **Layering.** core never imports services or transports. Services never import storage or transports and never run write SQL. The stdio proxy closure imports no keys, storage, transports, runtime, services, telethon, sqlcipher3 or whatsvault.
- **Audit trail.** Read `AGENT.md` and `CHANGELOG.md` before editing. At the tranche's end, append a dated `**Raouf:**` entry to both with Scope, Summary, Files changed, Verification and Follow-ups.

## Review Focus

1. **A second daemon, or a CLI, on the same state directory.** The runtime lock refuses the second daemon before any secret is read. `keys provision` refuses while a daemon holds the lock. Tests belong to E1 and E6.
2. **The key pointer names a version that no longer opens the database** (a crash mid-rekey). `open_with_recovery` repairs the pointer to the one key that opens it. If zero keys or two keys open it, the daemon does not start and names the fix. Test belongs to E2.
3. **The anchor file is missing or behind the chain head at startup.** Once the comms chain exists (`CHAIN_INITIALIZED` or later), the daemon starts with the integrity latch set (`AUDIT_INTEGRITY_DEGRADED`): reads work and new writes are refused. It never starts silently healthy. A freshly provisioned state with no chain and no anchor is expected, not degraded. Test belongs to E2.
4. **A background worker raises.** A recoverable failure (the provider is down, rate limited, a transient network error, a temporary archive failure) is logged by a fixed code and backs off, and the daemon stays up. An integrity or safety failure (audit mismatch, database corruption, a state-machine invariant, a credential-store inconsistency, lost session ownership) latches degraded, and no new external effect happens. It is never swallowed by the backoff. Test belongs to E5.
5. **`credential set` arrives with a value that fails the live proof.** The working credential stays active and the candidate is destroyed. The value never appears in the reply, the log or the audit event. Test belongs to E8.

### Task E1: The state layout and `comms keys provision`

**Files:**
- Create: `src/comms/runtime/paths.py`, `src/comms/runtime/provision.py`
- Modify: `src/comms/cli.py` (`keys provision` becomes a local command, like `daemon` and `doctor`), `src/comms/cli_commands/operator.py` (`LOCAL_COMMANDS`)

**Interfaces:**
- Consumes: `open_comms_db`, `KeyPointer`, `FileSecretStore`, `KeySlotStore`, `migrate` (comms), `bootstrap_comms_audit_keys`, `rot.rotate`, and `acquire_lock` (telegram runtime lock).
- Produces:
  - `CommsPaths(state_dir: Path)`, with properties `db`, `db_key_pointer`, `secrets_dir`, `slots_dir`, `anchor_dir`, `anchor`, `legacy_db`, `settings`.
  - `provision(paths: CommsPaths, *, now: datetime) -> ProvisionReport(created: tuple[str, ...])`.

**Ruling R-E4.** `keys provision` runs before the daemon exists (install step 2), so it is local and not an admin-socket request. It takes the same runtime lock and refuses while a daemon holds it. It is idempotent:
- **If `comms.db` is absent:** generate `comms-db-key` v1 into the secret store, set the pointer, create and migrate the database, then bootstrap the audit keys.
- **Every time:** provision each missing required purpose (`campaign-commit-key`, `cursor-key`, `oauth-signing-key`, `backup-key`, `cml1-client-seed` is per client, so skip it), and create the installation row.

It reports only purpose names, never material.

File rules (owner amendment):
- the daemon is not running, and an exclusive bootstrap lock is held;
- parent directories are 0700 and secret files 0600;
- every file is created atomically (temp file, fsync, `os.replace`; `O_EXCL` for new slots);
- a re-run is idempotent;
- existing material is never overwritten. If an existing key or slot is present but does not load or does not match its recorded key id, provision refuses (`ProvisionRefused("existing key material is damaged (run: comms doctor)")`) and never replaces it silently.

Bootstrap states, derived from the database and anchor, never stored separately:

| State | Condition | Next |
|---|---|---|
| `UNINITIALIZED` | no `comms.db` | `keys provision` |
| `PROVISIONED` | db and keys exist; no comms chain event; no anchor | `cutover run` (genesis) |
| `CHAIN_INITIALIZED` | comms chain events exist; the anchor may lag | the first anchor write |
| `READY` | the anchor matches the chain head | — |

`bootstrap_state(conn, paths) -> str` lives in `src/comms/runtime/state.py` (E2) and is reported by `comms doctor`.

Layout (the installer's `STATE_DIR`, default `/var/db/telegram-mcp`, overridable with `--state-dir`):

```
<state>/meta.db                 legacy (unchanged)
<state>/comms/comms.db          SQLCipher
<state>/comms/db-key.pointer    0600
<state>/comms/secrets/          0700, FileSecretStore
<state>/comms/slots/            0700, KeySlotStore
<state>/comms/anchor/head.anchor
<state>/comms/comms.json        0600, settings (E3)
```

**Ruling R-E5 (approved).** Settings are a 0600 JSON file, in a 0700 directory, `comms/comms.json`, kept apart from `comms.db` so that a database that won't open never stops the daemon from knowing how to start. | Class | Exceptions | Outcome |
|---|---|---|

| Integrity/safety | `ChainError`, `CommsDbKeyError`, `sqlcipher3.dbapi2.DatabaseError` (corruption), `AuditIntegrityDegraded`, an `AssertionError` or invariant error from the reducer, executor or recovery, `SecretStoreError`/`KeySlotError`, lost update-stream ownership, **and any exception not in the table** (fail closed) | `latch_degraded(conn, reason="WORKER_SAFETY_FAILURE")`, every effect-making loop stops, the listeners keep serving reads, and new writes are refused; database corruption also stops the daemon with a nonzero exit |

| Loop | Step | Every |
|---|---|---|
| `schedule` | `run_due(lease, conn, engine, now=clock())` | 15 s |
| `bot_updates` | `adapters.poller.poll_once()` (when configured) | 5 s |
| `webhook_inbox` | `adapters.worker.run_once()` (when configured) | 2 s |
